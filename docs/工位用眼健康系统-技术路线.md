## 技术路线（华为 ICT 创新赛道 · 赛题一）

整理日期：2026-10-18

## 1. 项目定位

一句话定位：

> 一个低成本、无摄像头的工位健康边缘节点，用光照、久坐、温湿度联合评估用眼负担，通过华为云 IoTDA、边缘/云端模型和 MCP 工具闭环，把“提醒”变成可执行、可确认、可追溯的健康建议。

核心目标：

- 桌面光照过暗/过亮时，端侧及时提醒，并同步到鸿蒙 App。
- 用 HC-SR501 的活动信号代理“工位是否有人”，统计连续久坐时长。
- 云端对历史数据做聚合和风险分析，生成每日用眼健康报告。
- 大模型通过 MCP 读取统计、生成报告；涉及蜂鸣器和阈值修改时，必须经 App 确认后下发。
- 比赛演示要能体现：端侧感知、云侧存储、AI 推理、MCP 闭环、鸿蒙 App 五个环节。

硬件清单：

| 模块 | 型号/说明 | 接口 |
|---|---|---|
| 主控 | 普中 Hi3861 鸿蒙开发板 | Wi-Fi 2.4 GHz |
| 光照 | GY-302 / BH1750 | I2C，常见地址 0x23 或 0x5C |
| 温湿度 | DHT20 | I2C，常见地址 0x38，协议兼容 AHT20 |
| 人体活动 | HC-SR501 | GPIO 数字输入 |
| 提醒 | 低电平触发有源蜂鸣器 | GPIO，建议经三极管驱动 |
| 串口 | CH340C | USB 转串口，COM3 |

## 4. 端侧技术路线

### 4.1 新建比赛工程

不要直接改 `08_led`。在 SDK 里新建：

```text
D:\hi3861_hdu_iot_application\src\vendor\pzkj\pz_hi3861\demo\50_eye_care\
```

以 `00_template` 或 `08_led` 为模板，保留：

```text
50_eye_care\BUILD.gn
50_eye_care\template.c
```

然后在 `demo\BUILD.gn` 中只启用：

```gn
"50_eye_care:template",
```

### 4.2 传感器驱动

BH1750：

- I2C 初始化，确认地址是 0x23 还是 0x5C。
- 上电后发送连续高分辨率测量命令。
- 读取 2 字节原始值，按数据手册换算为 lux。
- 1~2 秒采样一次，做中位数或滑动平均，抑制灯光闪烁。

DHT20：

- I2C 地址 0x38。
- 可直接复用 SDK 里的 AHT20 驱动（`10_i2caht20`），按 DHT20 时序微调。
- 5~10 秒采样一次即可，不需要高频读取。

HC-SR501：

- GPIO 输入，检测上升沿或高电平。
- 维护 `last_motion_ts`。
- 检测到活动后进入 `occupied`；连续 2~5 分钟无活动才转为 `empty`。
- 久坐只在 `occupied` 期间累计；离开 5 分钟后清零。

蜂鸣器：

- 低电平触发，建议使用模块自带三极管驱动。
- 提供短鸣、长鸣、双短鸣等 pattern。
- 云端断连时仍能本地报警，保证兜底能力。

### 4.3 本地状态机

建议状态：

```text
EMPTY ──检测到活动──▶ OCCUPIED
  ▲                      │
  └──连续 2~5 分钟无活动──┘

OCCUPIED 内累计 sit_cont_min：
  45 分钟 → 轻提醒
  60 分钟 → 强提醒
  离开 5 分钟 → 清零
```

注意：HC-SR501 检测的是“移动”，不是“静止存在”。人安静看书时可能长时间不触发，这是本方案的已知边界。比赛材料里要主动说明，并用“活动存在代理 + 超时保持”缓解；后续可选用 HLK-LD2410 毫米波传感器升级为真存在检测。

### 4.4 本地风险评分

第一版不需要上复杂模型，用“规则 + 轻量线性模型”即可：

输入特征：

- `lux_avg`：平均照度
- `lux_std`：照度波动
- `poor_light_ratio`：最近 10 分钟内偏低光照占比
- `sit_cont_min`：连续久坐分钟数
- `temp`、`rh`：温湿度

输出：

- `risk`：0~1
- `risk_level`：low / medium / high
- `reason`：例如“照度偏低 + 连续久坐”

这样端侧也能体现“模型推理/本地预处理”，不是单纯上报原始数据。

### 4.5 上报数据

建议 10~30 秒聚合上报一次，事件立即上报：

```json
{
  "ts": 1760000000,
  "seq": 1024,
  "lux_avg": 386,
  "lux_std": 42,
  "temp": 24.8,
  "rh": 51,
  "occupied": true,
  "sit_cont_min": 38,
  "light_state": "ok",
  "risk": 0.22,
  "fw": "0.1.0"
}
```

时间同步：

- 启动后通过 SNTP 校时。
- 上报统一用 UTC 时间戳，展示时转 Asia/Shanghai。
- 本地久坐计时使用单调时钟，避免改时间导致计时跳变。

## 5. 通信与华为云 IoTDA

### 5.1 产品模型

建议定义两个服务：

- `environment`：光照、温度、湿度
- `health`：是否有人、连续久坐、风险等级

属性示例：

| 属性 | 类型 | 说明 |
|---|---|---|
| `lux` | int | 照度 |
| `temperature` | decimal | 温度 |
| `humidity` | int | 湿度 |
| `occupied` | bool | 是否检测到活动 |
| `sit_cont_min` | int | 连续久坐分钟 |
| `risk_level` | string | low/medium/high |

命令示例：

| 命令 | 参数 | 说明 |
|---|---|---|
| `set_threshold` | lux_min/lux_max/sit_warn_min | 修改阈值 |
| `buzz` | pattern/duration | 触发蜂鸣 |
| `set_report_interval` | seconds | 修改上报周期 |

### 5.2 MQTT 主题

属性上报：

```text
$oc/devices/{device_id}/sys/properties/report
```

命令订阅：

```text
$oc/devices/{device_id}/sys/commands/#
```

命令响应：

```text
$oc/devices/{device_id}/sys/commands/response/request_id={request_id}
```

### 5.3 安全

- 设备使用 IoTDA 分配的设备 ID 和密钥，不使用示例里的固定账号。
- 优先使用 MQTTS 8883 + TLS；如果 Hi3861 RAM 紧张，先用 1883 跑通链路，最终版再切 TLS。
- App 不直接连 IoTDA，所有操作走自己的后端。
- 命令带 `request_id`，端侧做幂等处理，避免重复执行。

普中示例里的 `WIFI_SSID`、`WIFI_PAWD`、`DEVICE_ID`、`MQTT_USER_NAME`、`MQTT_PASS_WORD` 都是示例值，必须替换成你自己的。

## 6. 云侧与后端

### 6.1 推荐最小组合

```text
IoTDA → 规则引擎 → FunctionGraph → RDS MySQL
                              └→ OBS（可选，存日报/导出文件）
```

开发期可以先用本机 MySQL；比赛演示前迁移到华为云 RDS for MySQL。

### 6.2 数据表

建议最少四张表：

| 表 | 内容 |
|---|---|
| `telemetry` | 时间、设备、光照、温湿度、久坐、风险 |
| `events` | 光照异常、久坐提醒、离线/恢复 |
| `commands` | 命令类型、参数、状态、request_id、确认人 |
| `reports` | 每日汇总、AI 报告、生成时间 |

### 6.3 后端 API

用 FastAPI 即可，接口建议：

```text
POST /auth/login
GET  /devices
GET  /devices/{id}/latest
GET  /devices/{id}/history?from=&to=
POST /devices/{id}/thresholds
POST /devices/{id}/commands
GET  /devices/{id}/reports/daily?date=
```

原则：

- App 只拿后端 token，不拿云平台 AK/SK。
- 命令接口先写“待确认”记录，App 确认后再转发 IoTDA。
- 所有命令记录操作人、时间、结果，方便答辩时展示闭环。

### 6.4 部署选择

两种都可以：

| 方案 | 优点 | 缺点 |
|---|---|---|
| FunctionGraph + RDS | 运维少、按量计费、贴合华为云 | 调试不如本地方便 |
| 小 ECS + Docker + MySQL | 可控、好调试 | 需要自己运维 |

建议：开发期本机 FastAPI + MySQL，演示前部署到 FunctionGraph/RDS 或一台小 ECS。不要一开始就上复杂微服务。

## 7. 鸿蒙 App

使用 DevEco Studio（`D:\DevEco Studio`），ArkTS + ArkUI Stage 模型。注意：这是独立的 App 工程，不在 Hi3861 SDK 里。

页面建议四页：

1. **实时卡片**：当前照度、温湿度、是否有人、连续久坐、风险等级。
2. **历史曲线**：今日光照曲线、久坐时长、异常事件标记。
3. **设备与阈值**：设备绑定、光照阈值、久坐提醒阈值、上报周期。
4. **每日报告**：AI 总结、风险原因、建议、命令确认记录。

交互加分项：

- 今日风险指数环。
- 本次久坐进度条。
- 异常原因解释，不只给一个红点。
- 命令确认弹窗：AI 建议蜂鸣/改阈值时，用户点“确认执行”。

图表实现：

- MVP 用 ArkUI Canvas 自绘折线图即可。
- 后续可换 ECharts for HarmonyOS。

通知：

- 光照异常、久坐超时、云端报告生成时发 App 通知。
- 不把医疗诊断写进通知，使用“用眼负担偏高，建议休息”这类措辞。

## 8. AI 与 MCP 闭环

### 8.1 三层 AI

| 层 | 做什么 | 放在哪 |
|---|---|---|
| 端侧轻量评分 | 规则 + 线性模型，输出 risk 和本地动作 | Hi3861 |
| 云端风险模型 | 日/周聚合、异常检测、趋势分析 | FunctionGraph / 后端 |
| 大模型报告 | 解释原因、生成建议、调用受限工具 | 云端 LLM + MCP |

第一版云端模型不要追求深度学习。低维传感器数据用逻辑回归、孤立森林、统计阈值就够，重点是可解释和可复现。

### 8.2 MCP 工具白名单

```text
get_today_summary(device_id, date)
get_light_curve(device_id, from, to)
get_sitting_summary(device_id, date)
set_thresholds(device_id, lux_min, lux_max, sit_warn_min)  // 需 App 确认
buzz(device_id, pattern)                                   // 需 App 确认
```

### 8.3 闭环流程

```text
大模型读取统计
   → 生成“14:00-16:00 照度偏低、连续久坐 68 分钟”的报告
   → 创建待确认命令
   → App 弹窗确认
   → 后端写 commands 表
   → IoTDA 下发命令
   → Hi3861 执行并回执
   → App/报告显示执行结果
```

安全边界：

- 工具白名单，参数范围校验。
- 蜂鸣器和阈值修改必须人工确认。
- 限流、审计日志、失败重试上限。
- 大模型不能直接持有设备密钥，也不能直接连 MQTT。

## 10. 演示脚本

准备五个场景：

1. **正常工位**：照度合适、有人活动，App 显示正常。
2. **光照过暗**：遮住 BH1750，端侧蜂鸣短鸣，App 收到异常事件。

## 11. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| HC-SR501 只测移动 | 静坐时误判无人 | 2~5 分钟超时保持；材料中说明边界；可选毫米波升级 |
| BH1750/DHT20 地址或上拉冲突 | I2C 读不到 | 先单独扫描地址；确认模块上拉；分总线/分时初始化 |
| Hi3861 RAM/Flash 紧张 | TLS/MQTT 编译或运行失败 | 先 1883 跑通，再切 MQTTS；裁剪日志和缓冲区 |
| 只支持 2.4 GHz Wi-Fi | 连不上 5 GHz | 使用 2.4 GHz 热点；比赛现场提前测试 |
| 示例凭据写死 | 设备冲突/安全风险 | 全部替换为自己的设备 ID/密钥；不提交真实密钥 |
| Windows 路径过长 | 编译失败 | SDK 放在 `D:\hi3861_hdu_iot_application` 这类短路径 |
| 32 位 BurnTool 兼容性 | 烧录失败 | 使用已配置的 Java HiBurn 脚本；按一次 RST |
| 时间不同步 | 日报日期错 | SNTP 校时；服务端统一时区 |
| App 直连云平台 | 密钥泄露 | 一律走自己的后端 API |
| 功能铺太大 | 做不完 | 先 MVP：光照 + 久坐 + IoTDA + App 三页；AI/MCP 后补 |
