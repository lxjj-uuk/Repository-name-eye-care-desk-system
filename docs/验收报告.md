# 本地与云端竞赛版验收报告

验收时间：2026-10-30

## 已通过

### 后端与数据库

- FastAPI 在 `0.0.0.0:8080` 启动成功。
- `/health` 返回 HTTP 200。
- 登录、遥测写入、最新数据、历史数据接口通过。
- SQLite 数据库 `backend/eye_care.db` 重启后仍保留数据。
- 冒烟测试 `smoke tests passed`。

### AI 分析

- 未配置外部大模型时使用 `rule+risk-model`。
- 实测生成 1 份日报、2 条原因分析、3 条改善建议。
- App 报告页可显示从本地后端读取的真实分析结果。

### App

- 签名 HAP 已安装到 Pura 90 模拟器并运行。
- 模拟器通过 `http://10.0.2.2:8080` 持续读取本地后端。
- 实时页、历史页和报告页均能访问本地数据库。

### 硬件链路

- Hi3861 本地固件读取 BH1750、DHT20 和人体感应成功。
- Hi3861 通过 UART2 把数据发送给 ESP32。
- ESP32 串口可收到 `[uart] [eye-care] ...`。
- BLE 设备 `EyeCare-5B98` 可被手机连接。
- 通过 nRF Connect 写入蜂鸣命令后，ESP32 返回
  `buzzer_command_sent`，证明 BLE 到 ESP32 再到 Hi3861 的控制链路成立。
- WiFi 配网后可取得 IP，ESP32 可与后端建立 HTTP 请求。
- ESP32 已实现云端命令轮询：支持蜂鸣、阈值下发、报告周期和重置久坐。
- Hi3861 已实现 `BUZZ`、`THRESH` 和 `RESET` 串口命令。
- 本地热点联调实测遥测上传返回 HTTP 201，数据写入 SQLite。
- App 创建并确认云端蜂鸣命令后，ESP32 成功拉取、转发并 ACK，
  命令最终状态为 `acked`。
- 云端 `set_threshold` 命令端到端验证通过：后端状态为 `acked`，
  Hi3861 串口确认输出 `[eye-care] thresholds updated`。

## 当前限制

- 本机曾存在全局入站阻断规则；本地演示所需的该规则已精确禁用，其他
  防火墙规则保持开启。若系统策略被恢复，需要重新允许局域网访问 TCP 8080。
- DevEco HarmonyOS 模拟器没有蓝牙服务，App 的 BLE 页面只能在
  HarmonyOS 真机验证。
- LD2410B 已到货，但裸板为 1.27 mm 焊盘，尚未连接；当前人体检测使用
  原有数字量人体传感器接口。

## 云端竞赛版验收

- 阿里云轻量应用服务器地址：`http://39.106.195.83:8080`。
- Ubuntu 24.04，2 vCPU / 1 GiB，使用 SQLite 和 1 GiB swap。
- FastAPI 由 systemd 服务 `eye-care-api` 管理，服务器重启后自动启动。
- 公网 `/health` 返回 HTTP 200，登录接口正常。
- App 默认后端已切换到阿里云公网地址。
- ESP32 已烧录阿里云地址，通过手机 2.4 GHz 热点连接互联网。
- Windows 移动热点已关闭，本地 `8080` 后端未运行。
- Hi3861、ESP32 的 COM3、COM6 已从电脑移除，确认设备使用独立
  `5V` 电源供电。
- 独立供电后云端时间戳持续更新，遥测链路不再依赖开发电脑。
- 云端蜂鸣命令实测状态为 `acked`，消息为
  `buzzer command forwarded`。
- ESP32 SoftAP 配网已通过 iPhone 实机验证：连接无密码的
  `EyeCare-Setup` 后打开 `http://192.168.4.1`，保存目标 Wi-Fi，
  配网热点自动关闭，设备恢复云端上传。
- SoftAP 配网成功后再断电重启会自动重连最后保存的网络，不再需要
  nRF Connect。
- Kimi `kimi-k3.1-pro` 已基于真实 ESP32 数据生成报告：
  `source=llm`、`engine=api`。
- App 的“报告”Tab 每次进入都会重新获取云端最新日报。
- 公网移动网页 `http://39.106.195.83:8080/mobile` 提供实时、历史、
  设置和报告四个页面，并支持阈值下发、蜂鸣器测试和开启配网热点。

当前演示仍通过网络使用 HTTP 和共享演示 Token。正式交付前需要配置域名、
HTTPS、设备独立 Token、数据库备份和监控。
