# 本地试用版验收报告

验收时间：2026-10-29

## 已通过

### 后端与数据库

- FastAPI 在 `0.0.0.0:8080` 启动成功。
- `/health` 返回 HTTP 200。
- 登录、遥测写入、最新数据、历史数据接口通过。
- SQLite 数据库 `backend/eye_care.db` 重启后仍保留数据。
- 冒烟测试 `smoke tests passed`。

### AI 分析

- 未配置外部大模型时使用 `rule+risk-model`。
- 实测生成 1 份日报、2 条原因分析、3 条改善建议。
- App 报告页可显示从本地后端读取的真实分析结果。

### App

- 签名 HAP 已安装到 Pura 90 模拟器并运行。
- 模拟器通过 `http://10.0.2.2:8080` 持续读取本地后端。
- 实时页、历史页和报告页均能访问本地数据库。

### 硬件链路

- Hi3861 本地固件读取 BH1750、DHT20 和人体感应成功。
- Hi3861 通过 UART2 把数据发送给 ESP32。
- ESP32 串口可收到 `[uart] [eye-care] ...`。
- BLE 设备 `EyeCare-5B98` 可被手机连接。
- 通过 nRF Connect 写入蜂鸣命令后，ESP32 返回
  `buzzer_command_sent`，证明 BLE 到 ESP32 再到 Hi3861 的控制链路成立。
- WiFi 配网后可取得 IP，ESP32 可与后端建立 HTTP 请求。

## 当前限制

- 当前电脑的 Windows 防火墙策略会丢弃局域网设备发往 TCP 8080 的入站
  连接。临时关闭防火墙时实测 ESP32 收到 HTTP 201，数据成功写入数据库。
  正式演示前需要在防火墙管理界面允许 TCP 8080，或将后端部署到公网 HTTPS。
- DevEco HarmonyOS 模拟器没有蓝牙服务，App 的 BLE 页面只能在
  HarmonyOS 真机验证。
- LD2410B 尚未到货，目前人体检测使用原有数字量人体传感器接口。
- 当前“AI”为本地规则风险模型；接入大模型需要在 `backend/.env`
  配置 `LLM_API_URL`、`LLM_API_KEY` 和 `LLM_MODEL`。
- 当前本地服务依赖运行 `start-local.cmd` 的电脑。真正脱离局域网交付仍需
  公网 HTTPS 后端。
