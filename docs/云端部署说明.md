# 云端部署说明

## 当前环境

```text
云平台：阿里云轻量应用服务器
公网 IP：39.106.195.83
系统：Ubuntu 24.04
配置：2 vCPU / 1 GiB，使用 1 GiB swap
后端：FastAPI，直接监听 8080
数据库：SQLite
AI：Kimi kimi-k3.1-pro
```

竞赛阶段使用 `http://39.106.195.83:8080`，暂不绑定域名。该方式仅适合
演示和联调，正式使用应增加域名、HTTPS 和设备独立凭证。

## 服务器目录

```text
/opt/eye-care-desk-system       应用源码与 Python 虚拟环境
/var/lib/eye-care/eye_care.db   SQLite 数据库
/opt/eye-care-desk-system/backend/.env  云端配置和 API Key
```

API Key 仅保存在服务器 `.env` 中，权限为 `600`，不进入 Git。

## 服务管理

```bash
sudo systemctl status eye-care-api
sudo systemctl restart eye-care-api
sudo journalctl -u eye-care-api -n 100 --no-pager
```

健康检查：

```bash
curl http://127.0.0.1:8080/health
```

## 更新部署

重新执行：

```bash
curl -fsSL "https://ghfast.top/https://raw.githubusercontent.com/lxjj-uuk/Repository-name-eye-care-desk-system/main/scripts/cloud-bootstrap.sh" -o /tmp/cloud-bootstrap.sh
sudo bash /tmp/cloud-bootstrap.sh
```

脚本会保留 `/var/lib/eye-care/eye_care.db` 和已有的
`backend/.env`。

## 安全限制

- 当前使用 HTTP 和 `8080` 端口，未配置域名和 TLS。
- `API_TOKEN` 仍是演示值，不能直接作为生产凭证。
- 单机 SQLite 适合竞赛样机，不适合大量并发设备。
- 正式交付前应迁移 PostgreSQL、HTTPS、设备独立 Token 和备份监控。
